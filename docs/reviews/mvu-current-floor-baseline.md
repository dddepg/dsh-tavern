# MVU 中途启用后的当前楼层快照

2026-09-11：用户反馈纯文字卡转换为 MVU，并新增状态栏后，后台变量结算持续提示“未观察到对应变量变化”。

诊断包包含 12 次校验失败、1 次空 eventId 的变量写入被拒绝；其余结算没有对应的变量写入记录。单次事件身份拒绝不能证明所有结算都因 iframe 丢失 eventId 而失败。包内没有人物卡及状态栏脚本，无法排除卡内其他问题。

## 已复现的宿主兼容缺陷

官方 MVU 在非开局初始化时调用 `replaceVariables(..., { type: 'message' })`，只保存当前楼层。`handleVariablesInMessage` 则从当前楼层之前查找同时包含 `stat_data` 和 `schema` 的快照；查不到便直接返回。

浏览器使用真实官方构建、生产脚本桥与事务适配器，构造三层对话，仅最后一层有完整快照：更新不执行，产生相同的校验失败。单层对话对照组正常。这证明该路径存在缺陷，不代表诊断包足以确认群友的全部触发条件。

## 修复与验证

宿主构建保持优先使用前序有效快照；仅在没有前序快照时，回退到当前楼层的完整快照。不补写历史，不跳过 schema 校验，不放宽事件 ID 校验，不修改 MVU 指令解析。

同一浏览器场景修复后通过：校验拒绝后的重试成功，数值从 10 变为 9，事务阶段不直接写入权威 Chat。自动回归覆盖前序快照优先、当前快照回退、缺 schema 时拒绝，以及异步 MVU 回调保持 eventId 并等待写入确认。

诊断的 `runtime-dispatch.baseline` 新增无变量值的标记：`currentSnapshot`、`priorSnapshot`、`usesCurrentFallback`。后续可据此验证实际存档是否命中这一路径。

浏览器复现命令：`MVU_LATEST_ONLY=1 node tests/browser/mvu-tool-retry-browser-smoke.mjs`，打开其本机地址并点击“验证”。不使用真实人物卡或付费模型。

- 用原始状态栏脚本与生产 Helper 上下文更新协议验证：初值正常展示，字段变化后刷新，零写入请求。
