# 修改人物卡起始上下文实验

> 2026-10-01 已停用：新建“修改人物卡”任务不再标记 `cardEditContext`，与其他带卡的卡片会话统一保留卡片 Agent 人设，只在 system 中附带人物卡与常驻世界书参考（见 [foreground-story-prompt.md](../design/foreground-story-prompt.md#卡片-agent-的人物卡参考)）。已带 `cardEditContext.version = 1` 的旧会话继续按下文方式运行。

分支：`experiment/card-edit-system-context`。基线：`3ea3ee8`。

仅新建“修改人物卡”任务（`cardTask: edit`，且已选择人物卡）启用。其他任务不迁移。已带实验标记的会话若残留旧版自动生成的工作区草稿，会在打开时补入工作区消息；只有说明完全匹配时才从草稿移除，保留任务和用户补充。

请求结构：

1. System：原样复用前台 `play-card-snapshots` 和 `sessionStablePrefixSections`，包括人物卡、常驻世界书以及设置已启用的长期偏好。没有额外卡片 system 或工作区说明。世界书范围与前台一致，不额外注入所有关键词条目。
2. 原生 user → assistant → user 种子轨迹：直接调用前台模式，三条文案完全相同。
3. 工作区说明：在三条种子之后，作为原生 user 快照消息自动注入，不占用输入框。重试或重载不重复追加。
4. 用户任务：输入框只预填目标人物卡引用和修改任务说明。用户发送后作为正常 user 消息进入原生历史。没有额外卡片欢迎语。

工具仍使用卡片 Agent 的工具白名单，联网搜索始终可用。修改后以工具读取的资源为准；system 与前台一样是开局固定快照，不逐轮刷新。

使用原生追加式 Session 事件保存固定背景和种子；没有重写历史。实验标记 `cardEditContext.version = 1` 只写入新会话，固定文本沿用现有 `cardContextSnapshot` 和 `source.fixedSystemText`。

## 回退

本实验作为单个提交保存，未合并、未推送。可以切回基线或在实验分支撤销该提交，然后执行 `pnpm build:client` 和 `pnpm restart:tavern`。

无需删除人物卡、世界书或会话数据。回退代码后新建普通卡片任务恢复原行为。已创建的实验会话保留其原生假消息，不自动抹除；若要完全不带实验上下文，另开普通卡片任务。回退代码不会撤销用户在实验会话中实际保存的资源修改。
