# 世界书临时渲染：取消作业日志持久化

## 改动范围

基线为 `35fbc2c`。保留逐模板派发、现有浏览器协议、顺序作用域传递和每项任务刷新环境，仅给世界书投影增加 `renderProjection` 入口。同一 `render` 浏览器操作使用内存任务与内存回执，不再读取或覆盖 `template-work` 日志。旧的 runtime 实现没有此入口时继续使用 `render`。

普通 `render`、命令、初始化、输入、世界书准备和模型请求投影仍使用原持久化路径。浏览器自身的状态保存与 flush 不变；本次取消的是作业日志，不是业务数据保存。

## 失败与恢复

- 仍按会话串行执行，开始和完成均校验事件、执行器及租约。
- 已开始的任务断线或超时后直接失败，不自动重跑。EJS 可以调用外部接口，不能把任意脚本当成无副作用函数。
- 已完成回执的身份保存在内存，允许网络丢失确认后重传；缓存全局最多 256 项，仅存身份，不保留渲染内容。
- 进程重启不恢复临时任务或临时回执，调用者已随进程结束。迟到结果被拒绝，原任务不回放；用户可重新发起构建。
- 临时任务失败不保存作业诊断文件；错误仍返回调用者。普通任务的日志、回执和重启确认保留。

这不是全轮事务，也不提供任意外部副作用的 exactly-once 保证；现有执行路径同样不提供该保证。本次不引入自动重算、批量执行、资源缓存或快照版本协议，尽量缩小兼容性影响。

## 实测

沿用正式服务端模块及官方模板浏览器执行器的隔离合成基准：macOS arm64、Node 22.22.0、Chromium 145；26 条消息、266 条世界书、20 个控制器、两轮收敛，共 40 次 render。世界书 972839 字节，角色卡 770053 字节。两组依次独立运行，每组一次预热加三次采样，没有与测试套件并发测量。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 三次耗时 | 2296 / 2318 / 2360 ms | 777 / 758 / 766 ms |
| 中位耗时 | **2317.8 ms** | **765.6 ms** |
| 作业日志读取 | 40 | **0** |
| 作业日志写入 | 80 | **0** |
| 日志相关 fsync | 320 | **0** |
| 作业日志写入累计耗时 | 1380.4 ms | **0** |
| 世界书读取 | 41 | 41 |
| 角色卡读取 | 41 | 41 |
| 模板执行次数 | 40 | 40 |

整体中位耗时减少 **67.0%**，约为原来的三分之一。其余快照构建等指标也存在运行波动，不能把所有差值都算作磁盘日志本身的耗时。

每次运行均验证 20 条输出的内容及顺序、停用条目 getwi 读取、推测变量没有写入 Chat。基准额外断言正式持久化 store 开启时，世界书投影的作业日志读写仍为零。不是通过关闭整个 runtime 的 store 得到的结果。

精简原始数据见同名 JSON；after 数据是在基线提交上的未提交工作区改动中生成，JSON 明确标注 `workingTreeChanges`。未复测原始 Windows 用户角色卡、完整 DSH UI 或模型端到端耗时。
