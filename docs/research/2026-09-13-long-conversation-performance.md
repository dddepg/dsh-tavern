# Issue 19：长对话性能定位与修复

关联：[#19](https://github.com/flizzywine/dsh-tavern/issues/19)。本次只修复已复现的渲染开销，没有引入虚拟滚动、隐藏历史或改变模型上下文。

## 复现与结果

Apple M1 / 16 GiB / macOS，Playwright Chromium，1440×1000，原生测量不降速。DSH 0.1.2-rc.1、Tavern 1.7.0。空数据目录导入 365 条合成中文 Markdown，正文约 2.70 MiB，无 iframe、脚本、图片或模型调用。

宿主有历史分页；初次打开仅挂载末尾约 17 轮。点击十次“加载更早”后，365 条正文对应 914 个消息流节点、14,585 个 DOM 元素。流节点还包括上下文和轮次状态，不能当作消息条数。

同一会话、相同内容和操作（输入30个字母后清空，上下各滚动30次）：

| 指标 | 修复前 | 最终修复后 |
| --- | ---: | ---: |
| 最慢单字符输入操作 | 1060 ms | 50 ms |
| 主线程最长任务 | 1053 ms | 无超过50 ms的长任务 |
| 样式重算累计 | 1939.6 ms | 73.5 ms |
| JavaScript 执行累计 | 248.7 ms | 259.0 ms |
| DOM 元素 | 14,585 | 14,585 |
| 十次分页加载全部历史 | 约96秒 | 10.9秒 |
| 轨迹切回完整对话 | 30/120秒超时，后续复现渲染进程崩溃 | 993 ms |

输入时间包含 Playwright 命令往返，不是标准 INP。修复前恢复原 CSS 再测仍有961 ms输入停顿；未使用临时删规则的结果冒充修复后数据。

## 原因与修复

Tavern 的首页与开场白预览样式使用了祖先 `:has(...)` 后接通配子元素 `> *` 的规则。关系匹配让原本与游戏输入无关的界面样式参与长消息树的重算；即使首页、选卡窗口没有显示，仍会造成开销。分组动态删规则只能提供线索，最终以重新加载修复文件后的页面测量为准。

- 首页状态在 native Conversation 根节点的创建、phase及结构变化时派生，写成明确的 CSS class。正文流式更新与输入编辑不扫描历史。
- 空白 Session 有顶栏，继续保留输入框；无 Session 的首页保留品牌占位。根节点替换与插件卸载会清理标记和观察器。
- 开场白预览子元素的 `flex-shrink:0` 直接声明；普通块布局下该属性不影响排版，无需先查询预览后代。
- 日志按钮样式随导出组件挂载、卸载，因此去掉冗余的 `body:has(...)` 条件。
- 更新样式资源版本，避免旧 CSS 配新客户端。

## 验证

```sh
node bin/test-tavern.mjs
node tests/browser/long-conversation-browser-smoke.mjs
node tests/fixtures/text-colors-mount-perf.mjs
node tests/fixtures/long-conversation-native-perf.mjs STATE_JSON CONNECTION_JSON OUTPUT_DIR --navigation
```

完整测试：2030通过，无失败或跳过。浏览器回归包含首页、空白会话、延迟挂载输入框、根节点替换、清理、预览布局，以及活跃输入不扫描对话后代。

小型浏览器回归以17,905个DOM元素、4倍CPU降速测量：旧CSS的样式重算中位数66.2 ms，超过20 ms预算而失败；修复后约0.04 ms。可用 `TAVERN_PERF_CSS` 指定旧CSS文件、`TAVERN_PERF_SKIP_INSTALLER=1` 重放旧实现。

原生脚本需要独立合成会话：STATE_JSON 是 `{url,state}`（state来自Playwright storageState），CONNECTION_JSON 是测试服务的 `{url}`，输出目录必须已存在。脚本不会发送消息，但会填入并清空草稿，不要指向实际游玩会话。它确认测试卡名和全部历史挂载后才测量。

## 第二处：正文分色挂载

每个正文组件都会创建 CSS Highlight 样式，然后同步读取计算样式。批量挂载时形成“写样式—读样式”的循环。32 条短正文的浏览器回归测得32次样式重算、挂载100.1 ms；将首次扫描与重新启用交给已有的32 ms调度器后，降为1次重算、挂载2.4 ms。关闭与卸载仍立即清理，不改变正文 DOM。

原生完整历史切到轨迹后再切回，旧实现出现30/120秒操作超时，后续采样确认渲染进程 SIGTRAP 崩溃（未取得完整 JS profile，不据此推断浏览器内部崩溃原因）。修改后轨迹188 ms、切回对话974 ms；输入最慢39 ms，无超过50 ms的长任务。全部历史分页仍需82.3秒，继续单独排查服务端。

新增 `node tests/fixtures/text-colors-mount-perf.mjs` 检查批量挂载重算次数、延迟扫描取消、重启与卸载；可用 `TAVERN_TEXT_COLORS_SOURCE` 指定旧源码重放失败。原分色浏览器验证覆盖人物卡颜色、流式更新、开关和独立iframe；全量2025项测试通过。

## 第三处：插图状态查询

对话每条正文的插图组件挂载都会查询状态。单页浏览器 profile 显示约6.5秒等待中有6.2秒处于 idle；服务端 profile 则集中在 `sceneTarget`、历史前缀哈希、对话读取和克隆。原实现对每次查询计算整段历史的全部参考图沿用关系，即使游戏从未设置参考图。

- 参考图记录为空时不派生沿用关系；有记录时只计算图片来源、授权生效轮次的 key，继续校验当前剧情分支。原 key 算法与已保存图片路径不变。
- 同一会话同时到达的只读状态查询共享正在进行的对话读取；读取完成或失败立即释放，后续查询重新读取。修改、生成等操作不使用这一合并路径。
- 回归验证：100轮且无参考图时，首轮文本读取由102次降为1次；稀疏参考图不会遍历所有历史前缀，仍能识别原图并在正文分支变化后失效；不同会话不混用，失败读取可重试，后续正文修改可见。

最终原生回归通过：十次分页10.9秒、轨迹169 ms、切回完整对话993 ms，已等待分色和两次动画帧；输入最慢50 ms，滚动无超过50 ms的长任务。全部原始合成记录保留，截图已检查。

## 边界

这是 macOS/Chromium 下合成普通正文的复现，不替代反馈者 Windows/Edge、原人物卡和 iframe 脚本的实测。宿主仍使用历史分页，全量加载并非瞬时；没有引入虚拟滚动或改变模型上下文。测试没有调用文字或图片模型。
