# MVU 生命周期与会话读取的定向重构

## 范围

基于 #86、#89、#90，保留现有 Chat Journal 格式、时间线权威状态、MVU effect 提交与 DSH 固定版本。此轮收拢调度和读取约定，没有引入共享可写 Chat，没有改传输协议。

## 调度模块

`mvu-settlement-reconciler.js` 以每个 Session 一份记录管理进行中的 Promise、额外唤醒、定时器和生命周期信号。扫描使用独立身份，避免与 Session ID 冲突。每次异步读取/接续返回后确认记录仍有效；取消过但已经进入事件循环的定时器回调不能重新启动检查。销毁会使记录失效并中止传给 adapter 的信号。

修复前的确定性复现：先开始读取，销毁协调器，再返回旧读取，仍调用一次 resume。新增测试确认不会接续，也不会安排重试。

`settlement-jobs.js` 统一持有结算执行、重复调用合并、取消和销毁。旧任务结束不能删除新任务；取消和销毁不再从 finally 发出接续通知。模块销毁也覆盖任务已结束但异步完成通知尚未返回的窗口。正在进行的工作仍使用协作式 AbortSignal；不能把中止信号等同于撤销已完成的持久写入。

## 会话读取模块

执行层还补上了读档、世界书准备和读卡返回后的取消检查，并在世界书投影写入前检查信号。新增确定性回归覆盖读档或准备过程中销毁队列，防止异步返回后继续创建后台结算操作。

`session-view-reader.js` 对调用方只暴露读视图和生成同步响应；内部管理：

- 轻量状态与完整快照选择，以及绑定本次请求的缓存条目；
- revision、资源版本、模式的缓存身份检查；
- 投影版本和浏览器游标各自的增量范围；
- 缺失/过期增量、结构变化和冷启动骨架的完整回退；
- 慢旧请求不能覆盖已完成的新版本缓存。

入口保留渲染 adapter，不再保管缓存和 request-local WeakMap。`createSessionChatReader` 确保需要迁移时取得完整草稿，部分状态不会传给保存逻辑。

`chat-session-state.js` 同时持有轻量字段选择与动态视图消费者，包括活动状态、回退按钮、MVU 回执和结算轮次。新增状态字段时可在同一模块内更新输入与投影。普通读取和 Journal/Persistence 的隔离契约保持不变。

## 验证方式

#86/#90 的视图读取回归改为直接导入生产模块，通过公开读取入口建立缓存，不再截取入口文件函数到 VM 执行。历史 Surface 取证和部分完整结算编排仍有源码夹具，本轮未重写所有历史测试。

覆盖：销毁中读取/接续/扫描、取消后的迟到定时器、旧任务与新任务交错、领取超时后恢复、停止后不重投、持久保存后重启、缓存失效、结构变化、版本错配、慢旧投影、外部存档变化、迁移及隔离。

合成基准：453 条消息、约 22.7MB，`node --expose-gc tests/fixtures/issue90-read-cost.mjs output/state-refactor/read-cost.json --assert-optimized` 通过。20 次缓存命中约 13.1ms、状态查询约 7.2ms，完整 Chat 克隆均为 0；这些数字只用于确认 #90 的局部性能收益未被重构破坏，不代表真实 VPS 整轮耗时。

未执行真实浏览器/模型整轮验证；浏览器执行和视图渲染在模块测试中通过 adapter 隔离。未修改客户端资源。

最终合并运行 23 个相关测试文件：283 项全部通过，覆盖调度、结算恢复、会话读取、持久化、同步、回退及重新生成；入口语法检查和差异空白检查通过。
