# 模板环境：按内容复用只读投影

## 定位与思路

基线 `093a79d` 已取消世界书临时作业日志。本轮沿用 13 轮历史、266 条世界书、20 个控制器、两轮收敛共 40 次 render 的隔离 Chromium 基准，未调用模型或用户存档。

剩余开销主要是重复加工，不只是文件读取：每次环境同步通过 `worldBooks.bound` 构建编辑/召回视图，复制 rawEntry/raw，随后再导出完整文档。世界书和角色卡虽然未变，同步器仍每次序列化并哈希完整内容。角色卡在 characters 中同时提供扁平字段和 data 字段，大文本被重复序列化。

选择“按实际内容复用不可变投影”，而非全局暂停同步或用 Chat revision/TTL 猜资源是否变化：

- 增加 `worldBooks.templateSnapshot`，复用原有绑定解析、嵌入书转换、多书合并和开场快照选择逻辑，但不构建模板不使用的编辑条目、诊断及原文副本。
- 每次依然读取世界书文本；相同来源、名称及实际文本复用原生只读文档。嵌入/开场快照以 JSON 内容比较，避免靠对象身份或聊天版本猜测修改。
- 角色卡以实际 JSON 内容和世界书名称复用 characters 投影，避免重新生成并哈希两份等价大文本。
- 只对本模块递归冻结的自有 JSON 投影记忆指纹，不把任意浅冻结对象视为安全。Mutable settings、global variables、chat state 等仍按原路径同步。
- 仅在全量响应或有变化的字段真正需要传输时复制只读对象，调用者与浏览器获得可修改的独立副本，不能污染缓存。

没有更改模板执行顺序、浏览器协议、编辑/保存行为、历史增量连续性检查，或前一轮的作业回执逻辑。旧 worldBooks adapter 没有新接口时保持原路径。

## 资源与失败边界

世界书投影缓存最多 16 项、估算序列化权重 32 MiB；角色卡缓存最多 8 项、16 MiB。权重用输入和投影的 JSON 字符数估算，不等于真实 JS 堆上限。超大对象仍可读取但不保留，指纹和快照关联使用 WeakMap。

缓存不是权威数据。文件修改、损坏、删除、重新绑定、角色卡改名及全局变量变化不依赖 Chat revision。损坏文本必须报错，不能悄悄用旧投影。缓存冻结的是独立数据，不能冻结调用者传入的 Chat、卡或 openingWorldbookSnapshot.source。

多世界书仍调用原合并逻辑，未另行引入合并结果的依赖图缓存。因此多书组合的收益需要另测，不能直接套用单书数字。

## 本机实测

macOS arm64、Node 22.22.0、headless Chromium 145。世界书 972839 字节、角色卡 770053 字节。每组一次预热加三次测量，各组独立运行，不与全量测试并发。

本轮中位耗时下降 **52.3%**。角色卡和世界书内容仍校验新鲜度；不是用过期缓存换来的数字。暖态模板快照不再重复转换大世界书或计算相同投影的指纹，前台召回自身仍正常构建一次完整世界书视图。

所有样本校验输出内容/顺序、停用条目 getwi 读取和临时变量不写入 Chat；正式 store 开启时仍断言作业日志零读写。首次测量轮（预热轮）分别为 901 / 599 / 476 ms，但这是已初始化浏览器执行器后的第一轮，不是应用冷启动时间。

基准使用正式服务端模块与官方模板浏览器执行器。文件绑定和角色卡读取采用隔离的测试 adapter，因此实际应用的目录扫描、卡工作区投影或 Windows 文件系统耗时未包含在这些数字中；也未覆盖模型耗时或原始用户卡。旁边 JSON 保留精简原始指标，未提交改动测量明确标为 workingTreeChanges。

## 后续值得研究的方向

1. 多世界书可以按各来源快照身份与顺序复用合并结果，但必须覆盖重新排序、UID 冲突及来源变更。
2. 当前仍有 40 次独立环境同步和任务往返。批量控制器共享一次环境可进一步减少固定调用成本，但会改变中途修改可见性和失败粒度，需要单独设计。
3. 底层 durable file 读取会扫描待恢复快照，不能直接用 stat 或监听器跳过恢复检查。若减少实际读取，应由资源存储提供包含 pending 状态的可靠版本读接口，而非在上层加短 TTL。
