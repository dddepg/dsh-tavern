# Issue #43：世界书模板链路分段计时

2026-09-17，代码基线 `b431730`（已包含精简 render 引用和作业日志输入的优化）。

## 结论

本机当前瓶颈首先是逐作业持久化，其次是重复构建模板环境。不能据此把用户 Windows 上的分钟级等待归结为同一个比例，也没有复现报告者的原卡。

正式世界书模块、真实浏览器和磁盘存储下，266 条世界书 / 20 个常驻 EJS 控制器，每轮自然收敛两次，产生 40 个串行 render，暖态中位耗时 **3.516 秒**。模板投影执行本身仅约 0.042 秒；减少 EJS 能力或改变召回规则不是这一用例的优化重点。

## 方法

- macOS arm64，Node 22.22.0，Playwright Chromium 145.0.7632.6，headless。
- 独立临时目录；26 条消息（13 轮）、世界书 JSON 972,839 字节、人物卡 770,053 字节。
- 20 个 EJS 控制器顺序递增临时变量，并通过 `getwi()` 读取停用资料的长度。其余条目停用。校验最终 20 个输出的顺序、数值与文本，确认临时变量没有保存回 Chat。
- 复用正式 `createForegroundWorldbook`、`createWorldBookLibrary`、`createTavernScriptHostAdapter`、Chat Journal / Persistence、FullTemplateRuntime、ProfileDataStore / DurableFilePromotion。
- 浏览器加载已发布的模板产物；为精确分段计时，按正式 `connectTemplateSession` 的组合方式连接同一份 native-connection、session-tasks 源模块和产物的 initializeTemplatePlugin，仅在调用外围计时。
- 每组一次预热、三次测量，串行运行。每轮都重新走正式世界书投影，不强行指定收敛次数。
- 用 EventSource 及时唤醒执行器，并走 HTTP claim/start/complete。没有复刻 DSH Remote Snapshot Stream 的传播延迟、页面失联或首次唤醒问题。
- 世界书绑定在夹具中固定为一个独立文件，资源底层使用本地文件读取；不覆盖完整 FileResources 绑定索引、合并世界书或 opening 会话。没有 LLM 请求，也不是原始人物卡脚本的性能复刻。

## 对照实验

后三项是**只存在于 benchmark 的隔离实验**，用于估计优化空间，不是产品行为。

| 场景 | 暖态中位耗时 | 说明 |
| --- | ---: | --- |
| 小资源、同样 266 条 / 20 个控制器 | 2.970 s | 世界书 45.9 KB、卡 181 B，仍然 40 作业 |
| 大资源，当前实现 | **3.516 s** | 40 作业、120 次作业日志写入 |
| 大资源，仅跳过 queued 日志写入 | **2.766 s** | 保留 executing 和 completed；写入从 120 降到 80 |
| 大资源，实验性固定浏览器快照 | **2.767 s** | 不再逐作业读取服务端快照；仅适用于本测试不变的资源 |
| 大资源，实验性禁用全部作业日志 | **1.187 s** | 用于归因，不能直接采用：会丢失持久化执行意图和完成回执 |

每组耗时样本（首次为预热）保存在配套 JSON。实验组与基线的输出一致；这只证明该固定输入用例一致，不证明快照缓存面对其他页面写入、资源修改、回退或异步保存仍正确。不同实验不可直接相加推算综合收益。

## 基线分解

取大资源基线中位数对应的一轮（3.516 秒）。以下主要阶段互不重复；嵌套细分另列，不能再次相加。

| 阶段 | 次数 | 累计耗时 |
| --- | ---: | ---: |
| 作业日志持久化 | 120 | **2.072 s** |
| 服务端 getFullPromptTemplateState（含序列化） | 40 | **1.156 s** |
| 浏览器 plugin.project（含上下文准备及 EJS） | 40 | **0.042 s** |

浏览器完整 connection.refresh 累计 1.205 秒，包含上面的服务端快照读取和 HTTP，因此不能与其相加。plugin.refresh 仅约 0.0002 秒，当前浏览器宿主赋值不是主要瓶颈。

### 作业日志：小文件仍然昂贵

120 次写入只包含约 46 KB 紧凑 JSON 数据，但触发：

- 锁文件 fsync：120 次，0.436 秒。
- 数据文件 fsync：120 次，0.491 秒。
- 目录 fsync：240 次，0.941 秒。

合计 **480 次 fsync / 1.868 秒**，约占作业日志持久化时间的 90%。这解释了为什么上一轮去掉大 input 后仍有固定开销。fsync 由计时脚本包装 FileHandle.sync 实测，不是按源码次数估算。

Windows 分支会跳过目录 fsync；本机目录同步约占一半，不能将此占比照搬到报告者的 Windows 机器。Windows 的重命名重试、防病毒软件和磁盘条件还可能产生其他成本。

### 快照：响应很小，内部仍然重复读取

40 个快照响应合计 **8,360 B**，即每次约 **209 B**，增量传输已生效。

同一轮连同初始世界书准备，仍发生：

- 人物卡读取 82 次。
- 世界书文本读取 122 次。
- 世界书绑定 41 次，累计 0.555 秒。
- 世界书导出 40 次，累计 0.293 秒。

这些调用存在嵌套，不能全部累加。正式绑定会先读取绑定信息和条目，再读取记录；快照随后导出时又读取、解析和投影同一份世界书。环境指纹还会继续序列化和哈希大字段，即使最终只返回 209 B。

## 优化优先级

1. **先评估取消 queued 的同步落盘。** queued 尚未执行副作用，进程内 inspect 可使用内存状态。实验省约 0.75 秒（21%），同时保留执行前意图和完成回执。实施前需要明确重启后的排队诊断语义，并补领取超时、取消、迟到回执和跨进程重建测试。
2. **同一次快照构建只解析一次资源。** 让绑定、导出共享同一个已解析的记录，避免重复读人物卡、重复读世界书和构造 view。这比跨作业 TTL 缓存更容易保证一致性。不能仅因大部分时间没有写入就跳过版本检查。
3. **按资源版本复用环境投影及指纹。** Chat revision 不能代表世界书、卡、全局变量和设置的版本；分别校验版本，发生外部修改、会话切换或生命周期变化时失效。固定快照实验提供收益线索，不是可直接上线的实现。
4. **更大改造再考虑批量 render 或专用追加日志。** 一次投影把多个控制器放在一个作业中，浏览器内部仍按原顺序执行，可同时减少派发、快照和持久化次数。必须保留作用域传递、随机序列、逐条失败隔离、激活来源与收敛语义；已经开始的批次不能自动重跑。专用追加日志也需要完整的崩溃恢复、跨进程互斥和回执去重设计。

不建议关闭全部持久化、不建议凭 TTL 复用快照，也不建议为提速缩小收敛上限或并行执行互相传递变量的控制器。

## 两项优化落地后的复测

代码 `a373d4b` + `05a732e`：queued 作业只在内存中保存，执行意图与完成回执仍同步持久化；世界书绑定在单次调用内共享解析后的记录，模板导出复用该 document，下一次调用仍重新读取资源。没有跨请求 TTL 缓存。

同一脚本、同一大资源输入、相同 40 个 render；独立运行，不与测试套件同时执行。一次预热后，三个样本为 2.411 / 2.339 / 2.240 秒，中位数 **2.339 秒**，相较原基线 **3.516 秒降低 33.5%**。输出与预期完全一致，临时变量没有写入 Chat。

| 指标 | 原基线 | 优化后 |
| --- | ---: | ---: |
| 整轮中位数 | 3.516 s | **2.339 s** |
| 作业日志写入次数 | 120 | **80** |
| 日志持久化累计耗时（中位样本） | 2.072 s | **1.399 s** |
| 快照服务端累计耗时 | 1.156 s | **0.653 s** |
| 人物卡读取次数（含前台准备） | 82 | **41** |
| 世界书文本读取次数 | 122 | **41** |
| 模板投影执行累计耗时 | 0.042 s | 0.044 s |
| 快照响应总字节 | 8,360 B | 8,360 B |

排队中进程退出时不会留下该次 queued 记录；排队失败的 cancelled 诊断仍保存。现有已开始作业不自动重跑、回执去重、执行前落盘和跨进程完成确认语义保留。

回归覆盖：独立/内嵌/合并世界书、opening 快照、外部资源修改、换绑、调用者修改快照后的隔离；执行意图持久化之前不得开始运行、排队失败诊断以及完成回执重建确认。

原始复测数据：`output/playwright/issue43-optimized-final/large.json`；配套精简 JSON 的 `optimized` 字段保存本次阶段指标。仍然是本机合成基准，不能将 33.5% 作为用户 Windows 原卡的收益承诺。

优化后全量测试：2502 项通过，5 项跳过，0 失败。
