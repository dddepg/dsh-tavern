# 开局目录刷新优化验证

## 修改

- 打开新局后只等待会话列表刷新，移除无关的全量人物卡列表查询；带有资源种类的数据变更事件也只刷新对应列表。
- 人物卡列表使用轻量摘要投影，只读取名称和导入时间，不复制世界书等完整卡数据。
- 最多缓存 512 条摘要。每次查询检查文件的设备、inode、大小、纳秒修改时间和变更时间；变化后重新读取。不缓存失败，读取期间文件变化也不缓存该结果。
- 目录、图片存在性、剧本绑定和组织信息继续实时读取；不存在的工作文件仍进入原有读取路径，保留持久文件恢复能力。
- 未修改存档内容、模型请求、提示词或模板执行。

## 验证

使用此前用户提供的流式人物卡解码数据，在临时目录创建工作卡，以 HEAD 原版和修改后的实际 listCards 函数各执行六次。逐次比较完整目录输出一致，临时目录测试后删除。未访问模型。

| 路径 | 第一次 | 后续五次 |
| --- | ---: | --- |
| 原版 | 53.90 ms | 52.21 / 51.78 / 52.19 / 51.81 / 51.86 ms |
| 优化后 | 36.60 ms | 0.69 / 0.48 / 0.53 / 0.47 / 0.47 ms |

这是单卡目录的隔离服务端测量，不是整次开局 E2E，也不能直接套用于之前完整卡库平均 496 ms 的测量。缓存不会消除冷启动时的 JSON 解析。

定向回归涵盖：实际目录重复查询不再读取未变化的卡、新卡发现、外部修改、同时间同大小替换、删除、损坏修复、读写竞争、缺失文件恢复、打开新局不查询卡库、列表独立失败处理及开局重试生命周期。客户端重新构建并检查生成文件及完整 JavaScript 语法。
