# 开局预览传输优化

用户提供的《流式》人物卡有 615 条世界书、两个开场。旧流程给每个开场重复附带完整 runtime/worldbook，模板初始化后又返回整份准备对象。

新版客户端通过 `previewTransport: deferred-v1` 协商：开场列表只返回预览和草稿标识，模板初始化结束后取一次最终 runtime，在浏览器恢复各个开场的引用。世界书复用 runtime.context.worldbook；没有 runtime 的预览单独接收 worldbook。人物卡字段、脚本、世界书条目均保留。未协商的客户端保持原协议。

在同一张卡上按生产返回结构重建的 UTF-8 JSON 体积：

| 返回体 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 开场列表 | 47,006,075 B | 74,604 B |
| 初始化结果 | 23,466,147 B | 15,736,307 B |
| 合计 | 70,472,222 B | 15,810,911 B |

合计减少约 78%。体积实验中的 messageHtml 使用 projection.text，和生产 marked 输出有少量文本差异。这不是实际网络抓包，也不能换算成固定秒数收益。

回归覆盖生产 getCardOpenings 函数、新旧客户端协议、世界书完整性、开场切换、真实模板子进程；相关 47 项测试通过。浏览器验证使用真实 React/sidebar/iframe，RPC 为合成数据，不调用模型；11 个检查通过，包括世界书访问、收起恢复、失败重试与放弃开局。

仍保留约 15.7 MB 的脚本上下文；远程资源首次下载和模型首轮耗时不属于本次改动。没有验证用户 Windows 机器或手机端到端延迟。
