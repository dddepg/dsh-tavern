# 修改人物卡

目标是完成用户指定的局部修改，保留其余内容。使用当前引用的目标人物卡；目标或修改要求不明确时，只询问缺失的信息。目标明确就开始执行。

## 读取与选择工具

先用一句话说明本次要改什么、正在读取哪部分。只读取目标字段，需要关联证据时再扩大范围。

- 已有 MVU 卡的变量增删、改名、移动或开场初值：读取 [变量修改配方](references/mvu-variables.md)，用 tavern_card_draft 的 begin path 载入目标定义并局部修改。
- 已有 MVU 面板的标签、重复字段名、布局或样式：调用 `tavern_read_mvu_appearance`，参数 `path` 为目标副本。`editable=true` 时走下方美化流程。
- 普通设定、开场和文风：用 `tavern_read_card` 读取相关字段，通过 `tavern_update_card` 保存需要的变更，再用 `tavern_validate_card` 校验。
- 美化返回 `editable=false`：按返回说明读取目标卡相关扩展。普通正则美化使用通用改卡工具；已转换卡出现方案外修改、缺失定义或来源固化美化时，先说明具体限制和保留方案，不把生成元数据当普通扩展直接修改。
- 用户要求转换为 MVU：通过原生 `skill` 加载 `card-to-mvu`。用户提供游玩故障证据并要求诊断时加载 `debug-card`。

Skill 入口由原生 `skill` 加载，参考文件通过 `tavern_read_skill_reference` 按需读取。常规编辑使用资源工具，无需搜索磁盘上的 Skill 目录、其他人物卡或工具源码。只有现有工具确实无法表达用户要求时，才说明缺口并采用限定目标文件的备用方案。

## 局部美化流程

1. 读取返回的 HTML 与 bindings；需要未返回的片段时，按 `html.nextOffset` 续读并携带同一个 `revision`。外层已有字段名、值前又出现路径标签时，删除多余的静态标签，保留值占位与绑定。
2. 简短说明已定位的问题和准备修改的内容，例如“日期前多了一段路径标签，正在移除”。调用 `tavern_update_mvu_appearance`，提交 `path`、`revision`、`replacements:[{expected,value}]`。每项 expected 都是当前 HTML 中恰好出现一次的片段；多项以同一版本为准且不重叠。不需要回传整卡、初值或脚本。
3. 提交前说明“正在保存并校验”。工具负责同步定义、生成面板和摘要；成功且 `validation.valid=true` 即完成。无需另行读取全部生成物、再次转换或重复校验。

版本冲突时重新读取目标；匹配失败时扩大唯一原文片段。按错误中的具体字段修正，不重复提交相同失败参数。保留全部 `$N` 占位及 bindings；仅改文案不改变量定义或开场状态。

## 完成与进度

阶段变化时用简短正文告知用户正在做什么；过程较长时补充已完成的工作和当前原因，不编造百分比或预计时间。遇到工具限制明确报告，避免无反馈地扩展搜索。

保存并自动校验通过后，说明改动和结果即可。静态校验没有覆盖的浏览器布局或剧情效果可以作为范围说明，不能列为必须完成的“待真实验收”；只有用户明确要求才做真实游玩测试。
